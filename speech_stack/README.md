# speech-stack — распознавание, диаризация, опознание говорящего

Три службы за одним токеном, поднимаются одной командой на машине с NVIDIA GPU.
Русский, казахский, английский.

| служба | что делает | модель |
|---|---|---|
| **stt** | речь → текст, с пословными метками времени | faster-whisper на CTranslate2 |
| **diarization** | кто когда говорил; опознание человека по образцу голоса | `nvidia/diar_streaming_sortformer_4spk-v2` + `titanet_large` |
| **gateway** | один вход, один токен, чистые пути | Caddy |

---

## Быстрый старт

```bash
cp .env.example .env
openssl rand -hex 32          # положить в STT_TOKEN
docker compose up -d --build
```

Первая сборка долгая: веса распознавания конвертируются в формат CTranslate2
внутри образа, веса диаризации тянутся с хаба при первом старте.

Проверка — сначала пробы, потом рабочая ручка. **Это разные блоки конфигурации
и ломаются они независимо**, так что проверять надо оба:

```bash
curl -s localhost:8080/health          # 200 без токена
curl -s localhost:8080/health/diar     # 200 без токена
curl -s -o /dev/null -w '%{http_code}\n' localhost:8080/v1/models   # 401
```

Тест фильтра артефактов живёт внутри образа — он импортирует `decode.py`,
которому нужен torch:

```bash
docker compose run --rm stt python3 -m unittest test_artefact_filter -v
```

Сквозной пример — расшифровка с разделением по голосам в markdown:

```bash
export STT_TOKEN=...
./tools/example.sh запись.mp3 "Совещание" > протокол.md
```

## API

Всё, кроме `/health` и `/health/diar`, требует `Authorization: Bearer $STT_TOKEN`.
Неизвестные пути тоже отвечают **401** — снаружи не видно даже состава ручек.

### Распознавание

`POST /v1/audio/transcriptions` — multipart, совместимо с OpenAI.

| поле | значение |
|---|---|
| `file` | аудио; годится всё, что читает ffmpeg |
| `language` | `ru` \| `kk` \| `en` \| `auto` |
| `response_format` | `json` \| **`verbose_json`** — добавляет `segments` и `words` |
| `hotwords` | собственные имена через запятую |
| `prompt` | **не использовать** — на нашем материале резко портит результат |

`auto` определяет язык одним шагом декодера и возвращает `route` и
`detected_language`. Детектору разрешён **белый список** (`AUTO_LANGS`), и это
не перестраховка: argmax по всем ~100 языковым токенам whisper на шумной
телефонной реплике уходит к соседям казахского — `tt`, `ba`, `uz`. Чужой
языковой токен даёт не ошибки, а **сочинение**: ответ выглядит нормальным
текстом и не имеет отношения к записи.

**Поле `duration` в ответе — не длина файла.** Берите длительность из самого
файла.

### Диаризация

`POST /v1/audio/diarize` — `file`, опционально `min_segment_s`, `max_segment_s`.
Ответ: `segments[]` с `start`, `end`, `speaker`.

### Опознание говорящего

| ручка | что делает |
|---|---|
| `POST /v1/speakers` | регистрация: `name` + файлы-образцы |
| `GET /v1/speakers` | список зарегистрированных |
| `POST /v1/audio/identify` | `file` → кто говорит |
| `POST /v1/audio/verify` | `file_a` + `file_b` → один ли это человек |

## Модели и языки

**Русский и английский** идут на общую модель, **казахский** — на отдельный
слот. Разводить их обязательно: дообучение на казахском ломает обе другие
стороны, и заметнее всего английский.

**Казахские веса сюда не входят.** Репозиторий из коробки поднимается на
публичных весах whisper. Своя модель подставляется без правки кода:

```bash
EXTRA_MODELS_DIR=/путь/к/весам
WHISPER_CT2_PATH=/app/models/external/моя-казахская-ct2
```

**Одна настройка, которая на казахском решает больше, чем дообучение:**
`without_timestamps=not word_timestamps`. Токены таймстемпов портят ПЕРВОЕ
слово у заметной доли реплик, и стоковый whisper ведёт себя так же — то есть
это поведение модели, а не дефект конкретных весов. В `stt/decode.py` это уже
учтено.

## Потолок в четыре голоса — и как его обходят

**Модель диаризации различает ровно четыре голоса.** Пятый участник неизбежно
сливается с одним из четырёх. Это не настройка, а архитектура модели.

Проверяется просто: если в записи по тексту названы пять и более человек, а
ярлыков четыре — слияние уже произошло. Его видно и напрямую: говорящий под
одним ярлыком упоминает самого себя в третьем лице.

**Обход — расшифровка как второй, независимый от акустики канал.** По тексту
человек опознаётся по пяти признакам: прямое обращение, назначение, упоминание
в третьем лице (доказывает, что говорит НЕ этот человек), принятие поручения,
тематическая связность.

Границы способа: молчаливый участник остаётся безымянным; точка раздела внутри
слипшегося ярлыка — предположение, а не замер.

**Практическое следствие.** Поручения («ответственный такой-то, срок такой-то»)
извлекаются из ТЕКСТА и от диаризации не зависят вовсе. Протокол поручений
работает и там, где участников больше четырёх.

## Опознание говорящего: что нужно сделать до того, как ему верить

Порог сходства по умолчанию — `0.78`, и это значение **обязано быть
перемерено на вашем материале**. Порог, снятый на одном типе звука, на другой
не переносится: студийная запись, зал и телефон дают разные распределения.

Порядок калибровки без ручной разметки: возьмите пары «два говорящих из одной
записи» — их разделила диаризация, значит это заведомо разные люди, и метка не
может быть неправильной. Доля ложных принятий на таких парах и есть то, что
настраивается порогом.

**Чего этот способ не измеряет — полноту:** сколько СВОИХ вы отвергаете. Для
этого нужны пары «один человек в двух разных записях» с надёжной меткой, и
собирать их приходится отдельно.

**Голосовой слепок — биометрия.** Согласие на обработку получают до того, как
ручка окажется в продукте, а не после.

## Скорость и ресурсы

| | |
|---|---|
| распознавание | RTF около 0.06 |
| первый запрос после старта | медленнее на прогрев |
| диаризация | часовая запись — десятки секунд |
| VRAM: распознавание | ~5.6 ГБ на два слота |
| VRAM: диаризация | ~0.7 ГБ, обе модели резидентно |

Обе службы делят одну карту. `/health` диаризации до готовности честно
отвечает `loading` — ждать надо именно его, а не появления процесса.

## Как склеивать расшифровку с диаризацией

`tools/merge_transcript.py` делает это правильно, и порядок важен:

1. расшифровать запись **целиком** с `verbose_json` — модель видит контекст;
2. диаризовать ту же запись отдельно;
3. отдать каждое слово тому, кто говорил **в его середине**.

Середина, а не начало: на стыке реплик начало слова часто попадает в хвост
предыдущего говорящего, и реплики начинают перетекать друг в друга.

Резать аудио на сегменты и расшифровывать по одному — **хуже**: теряется
контекст, растут ошибки на границах, вызовов становится в десятки раз больше.

## Чего здесь нет

**Ограничения частоты обращений.** В Caddy без плагина не делается. Тело
запроса ограничено (200 МБ по умолчанию), но публичная служба на GPU — это
цель для исчерпания ресурса, и одного потолка тела мало.

**Синтеза речи.** Он живёт отдельно.

**TLS.** Предполагается, что шлюз стоит за тоннелем или обратным прокси,
который снимает TLS.
