# AI Meeting Copilot — автопротоколирование совещаний с фиксацией поручений

## Краткое описание

Протоколы совещаний ведутся секретарями вручную: это долго, а поручения, сроки и
ответственные теряются или искажаются. Система принимает запись совещания и возвращает
готовый протокол: транскрипт с разделением по говорящим, структурированный список поручений
(кто, что, к какому сроку) и краткое саммари.

Для кого: секретари совещаний и управленческие сотрудники, которые контролируют
исполнительскую дисциплину.

Кейс: [`docs/TASK/task.md`](docs/TASK/task.md). Проектное решение с разбором предпосылок и
границ: [`docs/designs/meeting-protocol-agent.md`](docs/designs/meeting-protocol-agent.md).

## Что реализовано

| Требование кейса | Где закрыто |
|---|---|
| 1. Распознавание речи участников | `speech_stack/stt`, развёрнуто на `stt.aibots.kz` |
| 2. Русский язык | маршрут `general:whisper-v6-ct2` |
| 3. Казахский язык | маршрут `ksc2:whisper-turbo-ksc2-ct2`, CER 0.000 на замере |
| 4. Шала-казахский | `language=auto`; CER **0.0511** на публичном корпусе с человеческой расшифровкой, [замер](docs/TASK/records/kk/shala-kazakh.md) |
| 5. Поручения с ответственным и сроком | `tools/extract_commitments.py`, модель на `vllm.aibots.kz` |
| 6. Диаризация с привязкой к человеку | `speech_stack/diarization` + склейка `merge_transcript.py` |
| 7. Экспорт протокола в файл | `front/lib/export-docx.ts`, `front/components/printable-protocol.tsx` |

Дополнительно: развёртывание в закрытом контуре заказчика — речевые службы и LLM свои,
исходники в репозитории.

## Как работает

1. Секретарь загружает запись совещания; она попадает в MinIO.
2. В Kafka уходит `RecognitionRequest` с идентификатором сообщения и ссылкой на папку.
3. Обработчик забирает файлы, конвертирует в MP3 и распознаёт речь целиком, с пословными
   метками времени.
4. Та же запись отдельно диаризуется. Каждое слово приписывается тому, кто говорил **в его
   середине**: на стыке реплик начало слова часто попадает в хвост предыдущего говорящего.
5. Склеенный транскрипт уходит в LLM, которая выделяет поручения с ответственным и сроком и
   собирает саммари.
6. `transcript.json` и `summary.md` возвращаются в ту же папку MinIO, в Kafka уходит
   `RecognitionResponse`. Интерфейс показывает протокол и отдаёт файл.

## Технологии

| Слой | Что используется |
|---|---|
| Распознавание речи | faster-whisper на CTranslate2; два маршрута: общий (ru, en) и казахский (собственная дообученная модель) |
| Диаризация | `nvidia/diar_streaming_sortformer_4spk-v2`, эмбеддер голоса `titanet_large` |
| Шлюз речевых служб | Caddy, один Bearer-токен на все ручки |
| Обработчик | Python, ffmpeg, Kafka-консьюмер, pydantic-контракты |
| Транспорт | Apache Kafka (топики запросов и ответов), MinIO (файлы) |
| Разбор транскрипта | Qwen3.8-27B-FP8 на vLLM, развёрнута на `vllm.aibots.kz` |
| Интерфейс | Next.js (App Router), Tailwind v4, каталог `front/` |
| Инфраструктура | Docker Compose, Traefik с Let's Encrypt, IaC-документация в `infrastructure/ansible/` |

## Архитектура

```
front/  ──① запись──►  MinIO  recordings/<meeting_id>/
  │                      ▲
  │ ② meetings.uploaded  │ ⑤ result.json
  ▼                      │
Kafka                    │
  │ ③                    │
  ▼                      │
meeting-copilot-container ─┘
  ├──► stt.aibots.kz  /v1/audio/transcriptions   распознавание
  ├──► stt.aibots.kz  /v1/audio/diarize          диаризация
  └──► vllm.aibots.kz /v1/chat/completions       поручения и саммари
  │
  └──⑥ meetings.ready | meetings.failed ──► front/
```

| Компонент | Каталог | Роль |
|---|---|---|
| Веб-интерфейс | `front/` | загрузка записи, статусы, протокол, экспорт в DOCX и PDF |
| Обработчик | `meeting-copilot-container/` | Kafka-консьюмер: распознавание, диаризация, склейка, разбор |
| Речевые службы | `speech_stack/` | исходники ASR, диаризации и шлюза |
| Транспорт и развёртывание | `infrastructure/` | Kafka, MinIO, Traefik, IaC-документация |
| Утилиты и замеры | `tools/` | извлечение поручений, бенчмарки распознавания |

### Речевые службы: `stt.aibots.kz`

Собственный стек, исходники в [`speech_stack/`](speech_stack/), развёрнут на машине с NVIDIA
GPU. Три службы за одним шлюзом и одним токеном.

| Ручка | Назначение | Токен |
|---|---|---|
| `GET /health` | проба распознавания | не нужен |
| `GET /health/diar` | проба диаризации | не нужен |
| `POST /v1/audio/transcriptions` | речь → текст, OpenAI-совместимо | нужен |
| `POST /v1/audio/diarize` | кто когда говорил | нужен |
| `GET /v1/models` | список моделей | нужен |
| `POST /v1/audio/identify`, `/v1/audio/verify`, `/v1/speakers` | опознание говорящего по образцу | нужен |

Авторизация — `Authorization: Bearer $STT_TOKEN`. Неизвестные пути тоже отвечают `401`, поэтому
снаружи не виден даже состав ручек.

Параметры распознавания, которые влияют на результат:

| Поле | Значение |
|---|---|
| `response_format` | `verbose_json` — даёт пословные метки времени, без них склейка с диаризацией невозможна |
| `language` | `ru` \| `kk` \| `en` \| `auto`; `auto` возвращает `route` и `detected_language` |
| `hotwords` | список собственных имён через запятую, повышает точность ФИО |

Замеры на записи 4 мин 34 с (русский), артефакты в
[`docs/TASK/records/artifacts/`](docs/TASK/records/artifacts/):

| Шаг | Время | Результат |
|---|---|---|
| Распознавание | 19.5 с | 61 сегмент, 567 слов с метками, маршрут `general:whisper-v6-ct2` |
| Диаризация | 2.5 с | 55 сегментов, 4 голоса |
| Склейка | мгновенно | 30 реплик с говорящими и таймкодами |

### Языковая модель: `vllm.aibots.kz`

Qwen3.8-27B-FP8 под vLLM, OpenAI-совместимый интерфейс. Развёрнута на той же GPU-машине,
что и речевые службы. Разбор транскрипта идёт здесь, поэтому **текст совещания не покидает
контур** — этого требует раздел «Ограничения» кейса.

```python
from openai import OpenAI
client = OpenAI(base_url="https://vllm.aibots.kz/v1", api_key=os.environ["VLLM_API_KEY"])
```

Имя модели — `qwen3-vl-30b-instruct`. Алиас исторический и оставлен намеренно: его уже знают
существующие потребители.

| Параметр | Значение |
|---|---|
| Контекст | 65 536 токенов на запрос |
| Одновременных запросов | 6, седьмой встаёт в очередь |
| KV-кэш | fp8, доля карты 0.65 |
| `GET /health` | 200 без токена |
| `GET /v1/models` без токена | 401 |

Карта общая с распознаванием, диаризацией и синтезом: тяжёлый прогон разбора замедляет
расшифровку. Ограничения частоты нет, единственная защита — токен, поэтому он приходит из
окружения и никогда не попадает ни в репозиторий, ни в код, исполняемый в браузере.

Замер на транскрипте тестовой записи: 58 с, извлечено 10 поручений с ответственным и сроком,
результат в [`docs/TASK/records/artifacts/commitments.json`](docs/TASK/records/artifacts/commitments.json).

## Установка и запуск

### Инфраструктура (Kafka, MinIO)

```bash
cd infrastructure
./local-up.sh
```

Скрипт создаёт `.env`, поднимает сервисы, дожидается готовности, проверяет что топики и
бакет созданы, и печатает адреса с паролями. Это единственная точка входа для инфраструктуры:
отдельного compose в корне репозитория нет.

### Речевые службы

Разворачиваются на машине с NVIDIA GPU:

```bash
cd speech_stack
cp .env.example .env
openssl rand -hex 32          # положить в STT_TOKEN
docker compose up -d --build
```

Первая сборка долгая: веса распознавания конвертируются в формат CTranslate2 внутри образа,
веса диаризации тянутся при первом старте.

### Обработчик

```bash
cd meeting-copilot-container
cp .env.example .env          # адреса Kafka и MinIO, токены речевых служб и модели
docker compose up -d --build
```

### Веб-интерфейс

```bash
cd front
npm install
npm run dev                   # http://localhost:3000
```

## Как проверить решение

Проба живости речевых служб — доступна без токена:

```bash
curl -s https://stt.aibots.kz/health
curl -s https://stt.aibots.kz/health/diar
```

Ответ содержит состав загруженных моделей и устройство.

Сквозной прогон одной записи, от файла до протокола с говорящими:

```bash
export STT_TOKEN=...
cd speech_stack
./tools/example.sh "../docs/TASK/records/Совещание №1.mp3" "Совещание №1" > протокол.md
```

Эталонный результат такого прогона лежит в репозитории и его можно сверить:
[`docs/TASK/records/artifacts/protocol.md`](docs/TASK/records/artifacts/protocol.md),
рядом — сырые ответы распознавания и диаризации.

### Распознавание смешанной речи: ничего не настраивать

```bash
curl -H "Authorization: Bearer $STT_TOKEN" \
     -F file=@запись.mp3 -F language=auto -F response_format=verbose_json \
     https://stt.aibots.kz/v1/audio/transcriptions
```

`language=auto` — и всё. Детектор сам уводит смешанную речь на казахский маршрут: на
31 записи из 31, без единого промаха. Указывать `kk` вручную не нужно, результат тот же.

**Чего делать нельзя:** ставить `language=ru` на том основании, что половина слов русские.
Это ровно вдвое хуже — 0.1147 против 0.0511.

Проверить это утверждение на публичных данных:

```bash
huggingface-cli download Tim2190/kazakh-codeswitch-asr \
    --repo-type dataset --local-dir ./kazakh-codeswitch-asr
export STT_TOKEN=...
python3 tools/bench_shala.py kk ru auto
```

Извлечение поручений из готового протокола:

```bash
export VLLM_API_KEY=...
python3 tools/extract_commitments.py \
    docs/TASK/records/artifacts/protocol.md /tmp/commitments.json
```

Эталон — [`docs/TASK/records/artifacts/commitments.json`](docs/TASK/records/artifacts/commitments.json):
10 поручений с ответственным, сроком в ISO и дословной цитатой назначения.

## Данные и интеграции

- Тестовые записи совещаний: [`docs/TASK/records/`](docs/TASK/records/). Записи
  смоделированные, что допускается условиями кейса.
- Речевые службы: собственный стек `stt.aibots.kz`, исходники в репозитории.
- Языковая модель: собственная `vllm.aibots.kz`, развёрнута на своей GPU-машине.
- Транспорт: Kafka и MinIO, поднимаются из `infrastructure/`.
- Внешние платные API распознавания не используются.

## Ограничения

- **Диаризующая модель различает ровно четыре голоса.** Пятый участник сливается с одним из
  четырёх; это архитектура модели, а не настройка. В тестовой записи названы пятеро
  участников и получено четыре ярлыка.
- **Шала-казахский** замерен на публичном корпусе `Tim2190/kazakh-codeswitch-asr` (31 запись,
  человеческая дословная расшифровка): pooled CER 0.0511 с `language=auto`. Замер включает
  контроли — пустая гипотеза 1.0000, бессмыслица 0.9486, чужой эталон 0.9306, — то есть стенд
  умеет провалиться, и число не пустое. Корпус состоит из **стендапа**: чистая запись, близкий
  микрофон. На телефонной полосе, в зале с эхом или при перебиваниях число будет хуже, и
  насколько — мы не знаем.
- **Разговорные стяжения приводятся к литературной форме** (`болад` → `болады`). Для протокола
  совещания это скорее плюс, но дословной записи не даёт. Ошибки сосредоточены на стыке языков — казахская вставка
  в русской фразе и первые слова после переключения. Реальная телефонная речь с шумом и
  перебиваниями не замерялась, методика и границы — в [`docs/TASK/records/kk/`](docs/TASK/records/kk/).
- **Опознание говорящего по тембру** развёрнуто, но образцов голосов не зарегистрировано,
  поэтому имена в протоколе не проставляются автоматически.
- Поле `duration` в ответе распознавания занижено; фактическая длительность считается по
  данным, см. `speech_stack/tools/merge_transcript.py`.
- Формат AAC (`.m4a`) не декодируется напрямую, требуется конвертация в MP3.
- Языковая модель и речевые службы делят одну видеокарту: параллельная нагрузка замедляет
  оба тракта. Потолок — шесть одновременных запросов к модели.
- Разбор транскрипта пятиминутной записи занимает около минуты.
- Полноценная интеграция с СЭД и промышленное развёртывание в объём работ не входили.
